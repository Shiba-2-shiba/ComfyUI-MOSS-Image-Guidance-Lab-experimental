# Native MOSS-Image: SCG / LEAP 実機手順

本書は静止画T2Iの検証手順です。両側でチェックポイント、解像度、CFG、スケジューラー、シードを揃えてください。SCGの配布グラフは1024×1024、CFG 3.5、simple、25ステップです。LEAPの比較には素のMOSSを使います。

## SCG: 同一シードでEulerと補正版

1. `workflows/moss_scg_ab.json` を読み込み、共有ローダーで手元のMOSS、テキストエンコーダー、VAEを指定します。配布時のLoRA強度は1.0、BlockTuneは `image_3_individual_qkv_partial` の `static` です。通常EulerとSCGは両方を適用した同一モデルを使います。対応するBlockTuneの適用区間は `static` です。
2. プロンプトを入力し、固定シードのままキューに追加します。SCG Euler の `profile` を空欄にすると、下記の解析スペクトルが自動で使われます。通常EulerとSCGは同じ空の潜在と初期ノイズから生成を始めます。
3. `output/moss_scg_ab` 内の `euler_*.png` と `scg_*.png` が比較対象です。初期値は `strength=0.15`、次sigmaの補正窓は `0.10–0.95` です。完全な無補正を確認するには strength を 0 にします。
4. 色調、粒状感、細かい模様、文字の可読性、破綻を確認します。参照を変える実験、強度を変える実験、シードを変える実験を一度に混ぜないでください。

SCGはEulerが更新した**次の**潜在状態を補正します。MOSSが使う正規化済み潜在空間で、同じ半径ビンの振幅をまとめて変更します。振幅ゲインは0.5–2.0に制限し、DCを維持します。終端sigma=0は補正の対象から外します。

独自の参照スペクトルを試す場合は、生成時と同じ解像度のRGB画像を `MOSS-Image SCG Profile` の `images` に入力します。ガイダーと同じBlockTune適用後のMODEL、デコードと同じVAEを接続し、出力を `SCG Euler` の `profile` につないでください。複数枚のIMAGEバッチではパワーを平均します。

### 画像なしで使う式 (7) の係数

クリーン潜在の目標パワーは `P(f) = 0.07676908 × f^(-1.47746396) + 0.13585077` です。`f` は半径ビン番号を潜在の長辺で割った値（cycles / latent pixel）です。次sigmaの目標は従来どおり、クリーン成分と白色ノイズ成分のパワーから計算します。

- **測定条件**　ワークフローで選択されている `flux2-vae_small.safetensors`（SHA-256 `d8d52ba036475f5fb07c8b435e176d3d97ebfa82f0d1a1c317f9cc1e25bd013b`）を使用。RGB写真を中央クロップとLanczosリサイズで1024×1024に揃え、128×64×64の潜在に変換しました。
- **調整用9枚**　scikit-image の astronaut、coffee、motorcycle_left、camera、grass、brick、coins と、Ultralytics の bus、zidane。画像ごとの放射方向パワーを平均し、DCを除く各ビンを等重みとして、予測と実測の自然対数の二乗誤差を最小化しました。
- **検証用4枚**　scikit-image の chelsea、rocket、gravel と Matplotlib の grace_hopper。同じ9枚で振幅を調整した `C/f²` と比べ、4枚の平均スペクトルに対する対数RMSEは 0.7762 → 0.2034 でした。これはスペクトルへの適合度です。生成時の画質や他のVAEへの一般化は別の評価項目です。

再測定には `scripts/fit_scg_spectrum.py` を使います。ComfyUIのPython環境で `--comfy` に本体ディレクトリ、`--vae` に重み、`--fit` と `--holdout` に別々の画像ファイル群を渡します。`--example` は追加の評価用画像1枚です。通常の生成時には調整用の画像やスクリプトは不要です。

### SCGのデバッグログ

ComfyUIを再起動し、画面を再読み込みすると、`MOSS-Image SCG Euler` に `debug_log` が表示されます。既定値は `off` です。実行ごとに `output/moss_scg_debug/<UTC時刻>_<ID>/trace.jsonl` が作られ、コンソールにもパスが表示されます。同じノードが実行キャッシュから返った場合は新しいログは作られません。

**野球の構図を比較する手順**

1. 既存の野球のPNGからワークフローを読み込み、seedを固定します。`SCG Euler` の `debug_log=jsonl+latents`、`sigma_min=0.84`、`sigma_max=1.0`、`strength=0` で実行し、Euler対照のログを取ります。グラフの通常Euler枝は引き続き画像比較に使えます。ログを書くのはSCGノードに接続した枝です。
2. 同じノードで `strength=0.15` に変えて実行します。窓外と終端を含む25更新すべてを記録します。コンソールのパス、ヘッダーのseed・strength・実行IDでログと生成履歴を対応させます。
3. リポジトリ直下から、下記の2つのパスを実際の実行フォルダに置き換えて比較します。CSVは1行が1ステップ・1サンプルです。

```powershell
python scripts/compare_scg_traces.py "C:\ComfyUI\output\moss_scg_debug\対照の実行フォルダ" "C:\ComfyUI\output\moss_scg_debug\SCGの実行フォルダ" > scg_comparison.csv
```

| 確認したいこと | 見る値と読み方 |
|---|---|
| 狙ったステップで動いたか | `step` は1始まり。`sigma` でモデルを評価し、`sigma_next` で補正を判定します。`reason` は `applied`、`outside_window`、`strength_zero`、`terminal` です。 |
| Euler更新と比べて十分に動かしたか | `scg_over_euler = ‖補正後−Euler更新後‖ / ‖Euler更新後−更新前‖`。0.1はそのステップのEuler更新の10%です。`scg_over_state` の分母はEuler更新後の潜在全体のノルムです。`scg_euler_cosine` は補正がEuler更新と同方向か逆方向かを表します。 |
| 低周波の目標から外れていたか、制限が効いたか | `target_power` とサンプルごとの `bands.power_euler`・`power_post`、符号付きの `log_error_pre/post` を照合します。正なら目標より過大です。`gain_requested` は制限前、`gain_applied` はDC保護・無効ビン・サンプル単位のフォールバックを反映した振幅倍率です。`clamped`、`valid`、`fallback_to_euler` も参照します。対象外ステップでは実効ゲインは1です。 |
| 全体平均が重要な差を隠していないか | ビン番号1以降を低周波から読みます。`bands.scg_over_euler` は帯域別の補正量比。`euler_power_cv` は帯域内パワーの変動係数、`between_channel_power_cv` と `within_channel_power_cv` はチャネル平均の違いと、各チャネル内の周波数成分のばらつきです。共通ゲインが1付近でも、内部のばらつきが大きいケースを識別できます。 |
| 補正が空間のどこに入ったか | `tile_rms_scg` と `tile_rms_euler` は潜在上の最大8×8領域別RMSです。行は上から下、列は左から右。`channel_rms_*` はチャネル別です。バットとボールに対応する領域を細かく見る場合は、NPZの `after−euler` を使います。 |
| 次のモデル評価で差が残ったか | CSVの `post_ab_relative_l2` は補正後の対照との差、次行の `denoised_ab_relative_l2` は次のモデル予測に現れた差です。`euler_ab_relative_l2` はそのステップでSCGをかける直前の差。各分母は対応するEuler対照のL2ノルムです。初回のモデル予測は補正前なので、すでに差がある場合は生成条件や実行のばらつきも確認します。これらは軌道の差の大きさを示します。接触の成否は同じ試行の画像で確認します。 |

**ファイル形式と保存量**

- `jsonl` は先頭に `run`、更新ごとに `step`、末尾に `end` を記録します。ヘッダーには実σ列、CFG、shift、ノイズ倍率、モデル名、テキスト条件の指紋、初期潜在のSHA-256、FFT規約、各ビンの周波数・係数数・クリーン参照パワーが入ります。モデルファイル名と実行コンテキストは取得できた場合に記録します。LoRAのファイル名や強度は同じ実行のPNGまたはComfyUI履歴で照合してください。
- `samples[b].bands` の配列はヘッダーと同じビン順で、0はDCです。`power_denoised` は更新前状態からのモデルのクリーン予測、`power_euler_delta` と `power_scg_delta` は各**差分テンソル自体**のパワーです。単位は正規直交FFTの平均二乗振幅です。ゼロ除算・非有限値・対象外の対数誤差はJSONの `null` です。`nonfinite_euler/post` はサンプル内の非有限要素数です。
- `jsonl+latents` は `initial.npz` と `step_0001.npz` 以降にFP32・NCHWの潜在を保存します。各ステップにモデル予測 `denoised` と補正前 `euler`、補正を試みたステップに補正後 `after` が入ります。ほかのステップの最終状態は `euler` です。1024×1024・1枚・25更新・12回補正で、NPZは約126 MiB、対応するEuler対照は約102 MiBです。計測はCPU転送・FFT・書き込みを伴うため、速度測定時は `off` に戻します。
- 比較CLIは初期潜在・条件・実σ列などを照合します。軽量な `jsonl` 同士でも補正量とバッチ単位の完全一致を比較できます。両方に潜在があれば、サンプル単位の3種類の軌道差も計算します。各ステップのJSONは逐次保存され、`end.status=complete` の実行を比較対象にします。中断までの行も単独で読めます。

### 帯域内の振幅配分を比較する

1. 対照では `within_bin_mix=0`、`budget_trace` は空欄、`debug_log=jsonl+latents` で現行SCGを実行します。以前の同形式のログも使えます。野球の比較条件は strength 1、σ窓 0.84–1.0、25ステップです。
2. 実験側は `within_bin_mix=0.5` にし、`budget_trace` に対照の実行フォルダ名を入れます。シード、strength、σ列、窓、参照スペクトル、条件を揃えます。0.25と1でも比較できます。0は従来の共通ゲイン、1は帯域内の非ゼロ係数を共通振幅に近づける方向へ全量を使う設定です。1でも各係数の振幅を一律に置換することはありません。
3. 上記の比較CLIの第1引数に現行SCGのログ、第2引数に実験ログを渡します。`batch_denoised_identical` が初回で True か、補正ステップで `scg_l2_ratio` が1に近いかを先に確認してください。両方にNPZがあれば `scg_delta_ab_cosine` で補正方向の一致度も確認できます。初回以降は2本の軌道が異なるため、各方向はそれぞれの軌道上での実測です。生成画像ではバットとボールの接触を同じ位置の拡大で比較します。

**何を揃えるか。** ログ指定時は、各ステップ・各サンプル・各半径ビンで保存された `power_scg_delta` を読み、振幅の変更量を正規化します。正規直交FFTなので、帯域ごとの補正エネルギーを揃えると潜在全体のL2補正量も丸め誤差の範囲で揃います。ログ欄を空にすると、その場のEuler更新後の潜在に現行SCGを適用した場合の補正量を使います。この設定では、別実行の現行SCGと軌道が分岐した後の補正量まで一致するとは限りません。

**何が変わるか。** 各ビンで現行SCGの振幅と平坦化方向を混ぜ、参照の補正量に合わせて移動します。位相、DC、振幅ゼロの成分を保ちます。振幅配分を変えると、同じ移動量で到達する帯域平均パワーは一般に変わります。従来の0.5–2.0制限は基準となる共通ゲインに適用し、実験側の個別係数は補正量と位相保存で制約します。記録した予算をその方向で実現すると振幅が負になる場合はエラーになります。

**ログ。** 実験ステップの `bands.budget_power` が帯域別の指定値、`power_scg_delta` が測定値です。`radial_gain_control` はその潜在に従来方式を適用するときの共通ゲイン。`effective_rms_gain` は実験後と実験前の帯域RMS振幅の比で、各係数に掛けた倍率とは区別します。

### FFT座標を比較する

1024×1024生成時、MOSSのモデル入力は128×64×64です。`spatial_measured` は正規化済みの値を32×128×128に並べ替えてFFTを行い、補正後に元の配置に戻します。VAEの逆正規化やデコードは挟みません。並べ替えはL2ノルムと白色ノイズの分布を保存します。各方式は、それぞれの座標でDCとフーリエ位相を保ちます。

| spectrum_space | 座標 | profile未接続時の目標 |
|---|---|---|
| `packed`（既定） | パック済み | 従来の式(7)のフィット |
| `packed_measured` | パック済み | 同梱9枚のパック座標での平均パワー |
| `spatial_measured` | 空間順 | **同一の9個のエンコード済み潜在**を並べ替えた後の平均パワー |

同梱の実測値は `calibration/flux2_1024.json` にあります。対象は上記の `flux2-vae_small` と1024×1024です。別のVAEや解像度では、同じ画像バッチ・同じVAEから作った `MOSS-Image SCG Profile` を両方式で共有します。このノードは各画像を一度だけエンコードして2種類のパワーを測ります。校正CLIの `--paired-output PATH` でも2種類の実測値を保存できます。

1. `within_bin_mix=0`、`budget_trace` 空欄、`debug_log=jsonl+latents`、`spectrum_space=packed_measured` で対照を生成します。
2. 同じseed・プロンプト・モデル等を使い、`spectrum_space=spatial_measured` に変更します。`budget_trace` に手順1の実行フォルダ名を指定して実行します。各更新・各サンプルの総補正L2を対照から読み込み、空間座標側の補正ベクトルをスカラー倍します。周波数帯間の配分は空間座標側で決まります。空欄のままなら空間座標側自身の補正量で生成します。
3. `scripts/compare_scg_traces.py` に上記の対照と候補を渡します。初回予測の完全一致、`scg_l2_ratio`（目標1）、`requested_total_l2`、`dose_scale` を確認します。総量を揃えた後の帯域ゲインは `gain_applied`、揃える前は `gain_before_total_match` です。ログの `spectral_shape` と `bin_counts` はFFT座標、NPZやハッシュは両方式ともモデルに渡すパック座標です。異なる座標の同じビン番号を直接比較する際は、折り返しの影響に注意してください。

## LEAP: 25回更新・15回評価の画質と時間

1. `workflows/moss_leap_compare.json` を読み込みます。共有チェックポイント入力のラベルは記録用の自己申告です。別モデルを試す場合はラベルを変更し、同じローダーからあらためて校正してください。ファイルをハッシュ検証する機能ではありません。
2. 校正は評価とは別のプロンプトとシード（初期値1000から連続）で、最初は2軌跡から開始します。校正はEuler-25の全軌跡で行い、同一MOSSモデルインスタンスのグラフ内で係数を共有します。セッションをまたぐ係数ファイルは用いません。プロンプト分布の一般化は保証されません。係数の絶対値の和が64を超える極端な行は数値安全策として拒否します（論文の設定ではなく、係数を切り詰める処理でもありません）。8または32軌跡を試す場合は校正コストも別に記録します。解像度、CFG、実sigma列などが変わったら再校正します。
3. 画像は `output/moss_leap_compare` の `euler25_*.png`、`euler15_*.png`、`leap25_15_*.png`。対応する `*_metrics_*.json` を確認してください。PNGとレポートは独立した保存ノードです。既存ファイルがあると番号がずれることがあるので、番号だけで同一試行と判断しないでください。
4. **Euler-25対LEAP** は同じ25更新のグリッド、**Euler-15対LEAP** は15回のguided評価という比較です。後者の15更新グリッドは前者と同一ではありません。三画像の評価プロンプト、固定seedと初期ノイズ、VAE、チェックポイント、解像度とCFGは共有します。

## 時間を測る

- **最初の試行は除外**。各方式を一度通し、校正を含む初回と、通常キャッシュが効くウォーム時を分けます。ほかのキュー、別のGPU推論、ライブプレビューを止め、モデルやグラフを途中で変更しません。
- **同一seedで再実行**。保存名だけを変えても推論は再実行されません。UIで再計測するときは `Benchmark nonce / not seed` を変更し、レポートのnonceが今の値か確認します。nonceは乱数には使いません。校正の結果はモデル・設定が同じ間はComfyUIのキャッシュで再利用されます。キャッシュを無効にした構成は別条件です。
- `guided_calls` はCFGを含むモデル要求回数、`physical_forwards` は実際に呼ばれた拡散モデルの回数です。正負条件が同じforwardに載るかは実行環境と条件次第なので、`forward_batch_sizes` と `forward_cfg_batches` も見ます。25→15 guided回は実行時間40%短縮を意味しません。
- `sampler_seconds` はガイダーによるサンプリングの同期込み実時間（この境界内の準備・転送・後処理を含む）。エンコード、VAEデコード、PNG保存やキュー待ちと同じ指標ではありません。CUDA/HIPでは対象デバイスの同期を境界に入れ、ステップごとには同期しません。
- 3回以上、順番を入れ替えて実行し、具体的な秒数の中央値と範囲を併記します。校正ログ、モデル名・量子化、GPU、PyTorch/HIP、ComfyUI版も控えてください。推論回数は減ったのに時間が変わらない場合だけ、別の測定としてプロファイラーを使う価値があります。

### ローカル計測CLI（任意）

フロントエンドのメニューからLEAPワークフローを **API形式** で保存します。編集用ワークフローJSONではなく、`class_type` と `inputs` が並ぶ形式です。起動中のComfyUIと同じPCで、端末から以下を実行します。ポートは実際の値に変更してください。

```powershell
python scripts/benchmark_leap.py API_GRAPH.json --port 8188 --repeats 3 --output leap_benchmark.json
```

このスクリプトは3方式を順番を変えながら動かしてPNGを保存し、ウォームアップを除いた集計と個々の計測をJSONに出します。CLIでは別のSave Textノードは動かしません。出力名は新しいものを指定してください。キュー投入から履歴で完了を観測するまでの実時間は、ポーリング待ち・VAE・PNG保存も含む別指標です。途中で他のキューを投入しないでください。実機の比較では、評価用のプロンプトとseedを変更した場合、API形式で再書き出します。
